Roadmap

Six phases. One is finished. The order is not negotiable — P3 builds the undo that P4 depends on, and forced uninstallation without a working undo is a data-loss feature, not a feature.

  1. P0

    Inventory

    Read the registry uninstall keys in both registry views, the MSI product database and the installed Store packages, merge them into one row per program, and show the result as a sortable list with search and a detail panel.

    Done
    • Both the 64-bit and the 32-bit registry view, so 32-bit programs are not silently missing
    • MSI product codes used to tie a registry entry to its product, with display names only as a fallback
    • Reads that fail become a visible warning rather than a silent gap
  3. P1

    Uninstalling

    Start the program's own uninstaller and wait for it to actually finish, then remove the leftovers that need no searching for — the install directory and the uninstall key itself.

    Next
    • Waiting on the whole process tree through a job object: NSIS and Inno Setup copy themselves to %TEMP% and exit the original process immediately
    • Files move to a backup from the very first release that deletes anything
    • Store packages go through the package manager rather than a command line
  5. P2

    The scan

    The actual feature. Search every place leftovers hide, score each finding, and never offer anything the protection list claims.

    Open
    • File system: Program Files, ProgramData, AppData, temp folders, prefetch, shortcuts, jump lists
    • Registry: vendor keys, App Paths, shared DLL refcounts, file associations, shell extensions, startup entries, services, firewall rules
    • System objects: services and drivers through the SCM, scheduled tasks through the task scheduler
    • Findings land in three buckets — safe, review, unsure — and each one carries its reasoning
  7. P3

    Undo

    The safety net that everything after it depends on. Nothing is deleted, only moved, and every operation is written to a journal before it runs.

    Open
    • Files keep their path structure, ACLs and timestamps inside the backup
    • Registry keys are stored as structured JSON and as an importable .reg file
    • An append-only journal means a crash mid-operation can still be rolled back
    • Optional system restore point before anything risky
  9. P4

    The extras

    The things people actually buy Revo for — deliberately last, because each one needs the undo from P3 to already work.

    Open
    • Junk hunter: find leftovers of programs that were uninstalled long ago
    • Startup manager, service and scheduled task views
    • Forced uninstall for programs whose own uninstaller is broken
  11. P5

    Shipping

    Everything between working software and something a stranger can install.

    Open
    • Translations
    • Code signing — without it SmartScreen treats a fresh binary as suspicious
    • An installer and automatic updates

Nothing is downloadable yet. Wave currently reads the inventory and nothing else. The moment there is a build worth installing, this site gets a download page — until then, saying so plainly beats a button that leads nowhere.

How this is built

Three crates, one rule between them.

Part Responsibility
wave-core What is installed and what belongs together. Knows nothing about Windows.
wave-win32 Registry, MSI, MSIX. Makes no decisions.
src-tauri The Tauri shell and the commands the interface calls.
src The interface: React, TypeScript, Tailwind.
site This page. Static, no build step.
